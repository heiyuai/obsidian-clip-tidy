# Clip Tidy

[English](README.md) | **简体中文**

用 AI 将剪藏的 Markdown 笔记整理到已有目录，附加摘要、标签和相关笔记链接，支持待确认队列、整理记录与撤销。可接入你自己的 OpenAI 兼容模型服务，也支持本地模型。

Clip Tidy 是独立的社区插件，与 Obsidian 官方无关联。本仓库仅包含 **Obsidian 整理插件**，无需安装配套浏览器扩展：用 Obsidian Web Clipper 或其他工具保存笔记后，即可交给它整理。

**仅支持桌面端 · Obsidian 1.8.7 及以上 · 中文界面和 AI 摘要**

## 功能

- 自动识别已有归档目录，也可手动编辑允许归档的目录列表。
- 支持启动时整理、新笔记进入时整理，以及手动整理。
- 保留原文，在文末附加摘要、标签、归档理由和相关笔记链接。
- 高置信度结果自动归档；把握不足的结果保留原位，等待你确认。
- 通过「已整理／未整理／待确认／失败」分区查看记录，搜索文章，打开原目录或目标目录。
- 保留原文备份；归档后笔记未被修改时，可撤销归档。
- 文件名冲突时追加数字后缀，例如 `文章 (2).md`、`文章 (3).md`。

## 安装

插件尚未提交社区目录审核，目前请手动安装：

1. 从[最新版本](https://github.com/heiyuai/obsidian-clip-tidy/releases/latest)下载 `main.js`、`manifest.json` 和 `styles.css`。
2. 在笔记库内创建 `.obsidian/plugins/clip-tidy/`，将这三个文件放进去。
3. 重新加载 Obsidian，在「设置 → 第三方插件」中启用 **Clip Tidy**。

不要复制他人的 `data.json`，其中包含个人设置、API 密钥和笔记备份。

## 首次配置

1. 在库内创建待整理目录，例如 `Clippings`，以及至少一个归档目录。
2. 打开「设置 → Clip Tidy」，填写待整理目录。默认值是 `待整理`，请改成实际的剪藏目录。
3. 归档目录默认自动识别；可直接编辑列表，每行一个。点击刷新按钮可恢复自动识别。
4. 填写模型接口地址、模型名称和 API 密钥。支持 OpenAI Chat Completions 兼容接口，例如 `https://api.openai.com/v1`，或本机 `http://localhost:11434/v1`。本地模型无需认证时可留空密钥。
5. 点击「测试连接」。测试仅发送一句测试文本，不发送笔记。
6. 阅读数据说明后开启「启用 AI 整理」，点击「立即整理」，或按需启用「启动时整理」和「新收藏自动整理」。

AI 整理**默认关闭**。完成配置并明确启用后，笔记才会发送到所选模型服务。插件免费；云端模型服务可能要求注册账号并按 API 用量收费。使用兼容的本地模型无需云端账号。

自动识别会排除待整理目录及其父子目录、隐藏目录，以及常见附件目录（如 `assets`、`attachments`、`images`、`附件`、`图片`）。手动指定的归档目录必须已存在，且不能与待整理目录重叠。

## 查看记录与撤销

点击左侧工具栏的归档图标，或在命令面板运行「Clip Tidy: 查看整理记录 / 撤销」。

- **已整理**：查看原目录和归档目录，打开文章、查看原文备份或撤销归档。
- **未整理**：查看收件箱文章并单独整理；已撤销的文章会暂停自动处理，直到手动重试或内容改变。
- **待确认**：展开摘要和归档理由，确认后归档。中断写入等需要检查的记录也会显示在这里。
- **失败**：修复连接或配置后，重新分析。

归档后若笔记被修改，或原路径被其他文件占用，撤销会拒绝覆盖。Obsidian 在移动笔记时可能改写相对链接，此时需要人工检查，可通过原文备份恢复。整理记录中的备份不能替代完整的笔记库备份。

## 联网与隐私

插件仅通过 Obsidian 的 `requestUrl` 向**你配置的模型接口**发起网络请求。默认地址为 `https://api.openai.com/v1`；测试连接或启用整理前不会发起请求。除 `localhost`、`127.0.0.1` 和 `[::1]` 可使用 HTTP 外，其他地址必须使用 HTTPS。请求发送至 `/chat/completions`。

每次整理请求会发送：

- 当前笔记的路径和完整 Markdown 正文，最多 50,000 个字符。
- 允许归档的目录名称，以及你填写的整理偏好。
- 最多 6 篇本地匹配的相关笔记的路径、标题、标签，以及每篇最多 1,200 个字符的摘录。

候选笔记根据标题、路径和标签在本地匹配。插件不会上传整个笔记库、下载图片、抓取网页、访问库外文件或收集遥测数据，也没有作者运营的后端服务。你选择的模型服务会收到上述内容，并按其自身条款和隐私政策处理。即使请求超时或你停止任务，模型服务仍可能计费。

设置、**未加密的 API 密钥**、分类结果，以及整理前后的完整笔记备份，保存在 `.obsidian/plugins/clip-tidy/data.json` 中。笔记库同步或备份可能包含此文件，请勿公开发布或附在问题反馈中。如需删除此文件，请先停用插件；删除后会重置配置并丢失撤销记录。历史记录不会自动清理，文件体积可能随使用时间增长。

## 使用限制

- 当前插件界面、摘要和归档理由为中文；中英文说明文档不代表插件界面已支持语言切换。
- 仅支持桌面端，尚未验证移动端。
- 只整理已保存的 Markdown 笔记，不包含浏览器点赞／收藏监听、推文线程展开、图片下载或语义去重。
- 置信度是模型自评，不是准确率保证；默认自动归档阈值为 0.8。
- 默认每批处理 10 篇，可选 5、10 或 20 篇。剩余文章等待下一次运行；运行期间进入的新文章可能触发后续批次。
- 超过 50,000 个字符的笔记会留在待整理目录。模型请求在 60 秒后超时；停止任务可阻止等待中的响应修改笔记，但无法撤回已经发出的请求。
- 内容未改变的失败或待确认笔记，不会自动反复重试。可在整理记录中手动重试。
- 相关笔记检索使用关键词，不使用向量；分类效果取决于模型和目录结构。

## 开发

需要 Node.js 22 及以上版本和 npm。

```sh
npm ci
npm test
npm run build
```

构建过程会检查 TypeScript 类型，并生成可读的 `main.js`。运行时的 `obsidian` 依赖由 Obsidian 提供。测试覆盖目录边界、模型响应校验、摘要安全格式、历史状态分组、文件名冲突、并发编辑、中断写入和撤销。自动化测试不代表对所有模型、主题和服务的兼容性保证。

发布新版本时，更新 `manifest.json`、`package.json`、`versions.json` 和构建文件中的版本注释。GitHub 发布标签必须与插件版本完全一致，不加 `v` 前缀；将 `main.js`、`manifest.json` 和 `styles.css` 分别作为附件上传。
